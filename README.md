# 电商客服工单分级处理与升级工作流（Dify）

> 基于 Dify 搭建的电商客服工单自动化工作流，约 **25 个节点 / 33 条边**，覆盖 5 类常见问题的自动分流，并支持升级预警双通道（飞书 Webhook + 本地 qwen2.5:7b 推理）。

**🌐 简体中文 | [English](./README_EN.md)**

## 项目简介

本工作流以**客服收到的客户留言 + 订单号 + 客户等级**为输入，由本地大模型完成**意图识别 / 情感分析 / 紧急度评估**，并依据判定结果自动：

- **意图分类**：售前 / 售后 / 投诉 / 其他 4 大类
- **问题细分**：物流 / 商品质量 / 退换货 / 价格促销 / 账户支付 5 小类
- **升级预警**：命中「愤怒」或「紧急程度 ≥ 4」时，自动通过**飞书 Webhook** 触发主管预警通道
- **回复生成**：由大模型生成处理方案（责任部门 + SLA）
- **兜底分支**：「其他」类问题走礼貌引导，避免空跑主链路

## 技术栈

| 类别 | 工具 / 模型 |
|---|---|
| 工作流编排 | Dify（可视化编排） |
| 大模型推理 | Ollama 本地部署 qwen2.5:7b |
| 消息通知 | 飞书自定义机器人 Webhook |
| 代码节点 | Python（构造飞书 msg_type 协议） |
| 重试策略 | HTTP 节点 3 次重试，配置退避 |

## 升级预警双通道

为避免「稍等一下」型客户流失与「愤怒型」客户升级投诉，本工作流设计**双通道预警**：

1. **主管飞书预警通道**：Python 节点构造飞书消息体（msg_type 协议）→ HTTP 节点调用机器人 Webhook → 配置 3 次重试。
2. **客服工单通知通道**：自动生成工单详情，包含订单号、客户等级、留言摘要、建议责任部门与 SLA。

> 仅当「情感极性 == 愤怒」或「紧急程度 ≥ 4」时触发，普通问题不打扰。

## 文件说明

- **`dify-customer-service-workflow.yml`**：Dify 工作流 DSL 文件，可在 Dify 控制台「导入应用 → 自定义」中直接导入。

## 如何复现

1. 准备一台已部署 qwen2.5:7b 的机器（Ollama 拉取模型）。
2. 准备飞书机器人的 Webhook URL（任意群）。
3. 将 `dify-customer-service-workflow.yml` 导入 Dify：控制台 → 工作流 → 导入 DSL → 选此文件。
4. 在「开始」节点配置**订单号 / 客户等级 / 留言**输入项。
5. 在「HTTP 请求」节点（飞书 Webhook）替换为你自己的 Webhook URL。
6. 启用工作流，从前端或 API 调用测试。

## 测试样本（建议）

- **物流类**：「我的快递 3 天了还没到，订单号 xxx」
- **退换货**：「商品质量不行，我要退货」
- **价格促销**：「双 11 没保价，现在能不能补差价」
- **账户支付**：「充了 100 没到账」
- **升级预警**：「你们这破服务，我要投诉到 12315！！！」← 紧急度 5，触发主管预警
